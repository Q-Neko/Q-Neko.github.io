# Adding content

A practical, step-by-step guide for adding a new entry of each content type — and a new page. This complements the [README](../README.md), which is the reference for schemas and conventions; this doc is the "what do I actually do" checklist.

Before you start, get the dev server running (see [README → Quick start](../README.md#quick-start)):

```sh
nvm use v24
npm run dev      # http://localhost:4321
```

> [!Note]
> Search results and the per-item search landing pages only exist in a **production build** (`npm run build && npm run preview`), not in `npm run dev`. See [README → Search](../README.md#search).

## How content is organized

All collection schemas live in [src/content.config.ts](../src/content.config.ts); the content itself lives under [src/content/](../src/content/). Two things decide where a file goes:

- **Language is the directory, not frontmatter.** `news`, `events`, and `results` each have `en/` and `ja/` subfolders. A file in `en/` only appears on the English site; a file in `ja/` only on the Japanese site. To show an entry in both languages you add **two files** (one per folder).
- **Media Corner and Partners are language-neutral** — single JSON files shared by both locales.

Quick map of which file(s) to touch:

| You want to add… | Edit | Bilingual? | Jump to |
| --- | --- | --- | --- |
| A news post | new `.md` in `src/content/news/{en,ja}/` | one file per language | [News](#news) |
| An event | new `.md` in `src/content/events/{en,ja}/` | one file per language | [Events](#events) |
| A result / deliverable | new `.json` in `src/content/results/{en,ja}/` | one file per language | [Results](#results) |
| A press release / media article | append to a JSON array in `src/content/media/` | single shared entry | [Media Corner](#media-corner) |
| A downloadable logo | drop a file in `public/logos/media/` | n/a (auto-discovered) | [Brand assets](#brand-assets-logos) |
| A partner logo | append to `partners.json` + drop logo | single shared entry | [Partners](#partners) |
| A whole new page | new `.astro` wrappers + nav + i18n | one wrapper per language | [A new page](#a-new-page) |

## News

Markdown, one file per post. Schema: [`news`](../src/content.config.ts#L17). Reference example: [introducing-q-neko.md](../src/content/news/en/introducing-q-neko.md).

1. Create `src/content/news/en/<slug>.md` (and `src/content/news/ja/<slug>.md` for the Japanese site).
2. Add frontmatter — **all fields except `image` are required**:

   ```yaml
   ---
   title: "Post title"
   slug: "url-slug"               # the page lives at /news/<slug> (and /ja/news/<slug>)
   date: 2026-01-01               # a real date, not a string
   description: "Short text shown on the card"
   author: "Q-Neko"
   type: "News"                   # free text; shown as the card's meta label
   tags: ["EU-JAPAN", "Quantum Computing"]
   image: "/news/<slug>/cover.jpg"   # optional
   ---

   Markdown body goes here.
   ```
3. Write the body in Markdown (headings, lists, images all work).
4. **Images:** put them under `public/news/<slug>/` and reference by path, e.g. `image: "/news/<slug>/cover.jpg"`. See [README → Images](../README.md#images-and-static-assets).

**What happens automatically:** the post shows up on [/news](../src/pages/news.astro), gets its own page at `/news/<slug>` via [news/[title].astro](../src/pages/news/[title].astro), is a search record in a production build, and can surface in the homepage [Recent Activity](../src/components/mainPage/RecentActivity.astro).

## Events

Markdown, one file per event. Schema: [`events`](../src/content.config.ts#L35). Reference example: [kickoff-workshop-2026.md](../src/content/events/en/kickoff-workshop-2026.md).

1. Create `src/content/events/en/<slug>.md` (and the `ja/` twin).
2. Frontmatter (`location` and `image` optional, the rest required):

   ```yaml
   ---
   title: "Event title"
   slug: "url-slug"               # page at /events/<slug>
   description: "Short text shown on the card"
   startDate: 2026-01-20          # real dates
   endDate: 2026-01-22
   location: "Tokyo, Japan"       # optional, shown as the card meta label
   image: "/events/<slug>/cover.jpg"   # optional; falls back to placeholder
   ---

   Markdown body.
   ```
3. Images go under `public/events/<slug>/`.

Per-event page is generated by [events/[slug].astro](../src/pages/events/[slug].astro); listing is [/events](../src/pages/events.astro).

## Results

JSON, one file per result. Each entry points at a PDF. Schema: [`results`](../src/content.config.ts#L54). Reference example: [kickoff-poster.json](../src/content/results/en/kickoff-poster.json).

1. Put the PDF in `public/files/results/` (e.g. `public/files/results/d1.1-collaboration-plan.pdf`).
2. Create `src/content/results/en/<name>.json` (and the `ja/` twin):

   ```json
   {
     "title": "D1.1 — Collaboration Plan",
     "type": "deliverable",
     "date": "2028-02-15",
     "pdf": "d1.1-collaboration-plan.pdf",
     "image": "/files/results/d1.1-cover.jpg"
   }
   ```
3. `pdf` is just the filename — `/files/results/` is prefixed automatically.
4. `type` **must** be one of: `deliverable`, `milestone`, `publication`, `software`, `presentation`, `poster` (the enum in [content.config.ts](../src/content.config.ts#L52)). The displayed label is the localized version from `t.pageContent.results.filters[type]`. `image` is optional.

Listing is [/results](../src/pages/results.astro); each result gets a thin search landing page that redirects to the PDF via [results/[slug].astro](../src/pages/results/[slug].astro).

## Media Corner

Unlike the above, Media Corner items are **language-neutral** — you add **one** entry that appears on both the EN and JA pages. Schema: [`mediaItemSchema`](../src/content.config.ts#L78). Full field reference: [README → Press releases & media coverage](../README.md#press-releases--media-coverage).

Pick the right file in [src/content/media/](../src/content/media/):

- [press-releases.json](../src/content/media/press-releases.json) → **Press releases** tab (our own announcements)
- [media-coverage.json](../src/content/media/media-coverage.json) → **Media coverage** tab (external articles about Q-Neko)

Append an object to the array:

```json
{
  "id": "hpcwire-new-era",
  "title": "Q-Neko Project Drives EU-Japan Quantum Collaboration Into a New Era",
  "source": "HPCwire",
  "language": "EN",
  "date": "2026-02-11",
  "url": "https://www.hpcwire.com/off-the-wire/...",
  "order": 0
}
```

- `id` must be unique within the file (kebab-case). `url` must be a valid absolute URL.
- `date` is optional (undated entries sort last); `order` is a tie-breaker (default `0`).
- `language` is the original language of the piece (`EN`, `FI`, `JA`, …) and is only a label — the item still shows on both locale pages.

Each media item also gets its own search landing page via [media/[slug].astro](../src/pages/media/[slug].astro), so it becomes searchable automatically.

### Brand assets (logos)

The **Communication materials** tab is **auto-discovered** — there is no manifest to edit ([loader](../src/content.config.ts#L102)).

- **To add a logo:** drop a `.png`, `.svg`, `.jpg`/`.jpeg`, or `.webp` into [public/logos/media/](../public/logos/media/). It appears automatically, sorted by filename, with the filename as its label — so name it sensibly (e.g. `Q-Neko-logo-text.png`).
- The "Download all" ZIP is **built at build time** from the same folder by the [logoZip integration](../src/integrations/logoZip.mjs) — nothing to commit or keep in sync.

## Partners

Homepage partner logos come from one language-neutral file, [partners.json](../src/content/partners/partners.json) ([collection](../src/content.config.ts#L69)). Rendered by [Partners.astro](../src/components/mainPage/Partners.astro).

1. Drop the logo into `public/logos/Roll-up-logos/`.
2. Append an entry to the `partners` array:

   ```json
   {
     "country": "Finland",
     "region": "EU",
     "name": "CSC",
     "long_name": "CSC - IT Center for Science",
     "logo": "/logos/Roll-up-logos/csc_se.svg"
   }
   ```

`logo` is a `public/` path. `region` groups the partner (e.g. `EU`, `JP`).

## A new page

Mirrors [README → Adding a new page](../README.md#adding-a-new-page). Pages come in pairs (EN + JA) and almost always wrap a shared body component. Use an existing pair like [newsletter.astro](../src/pages/newsletter.astro) / [ja/newsletter.astro](../src/pages/ja/newsletter.astro) as the template.

1. **Add the page title string** (so the `<Banner>`/tab title is translated):
   - Add the key to the `Translations` interface in [src/i18n/types.ts](../src/i18n/types.ts) (under `pages`).
   - Add the English value in [src/i18n/en.ts](../src/i18n/en.ts) and the Japanese value in [src/i18n/ja.ts](../src/i18n/ja.ts). TypeScript errors if a locale is missing the key. See [README → i18n](../README.md#internationalization-i18n).

2. **Create the shared body component** `src/components/pages/MyPage.astro`, taking a `lang` prop:

   ```astro
   ---
   import { useTranslations } from "../../i18n/index";
   const { lang } = Astro.props;
   const t = useTranslations(lang);
   ---
   <section>
       <h1>{t.pages.myPage}</h1>
       <!-- page content; build locale-aware hrefs with: const base = lang === "ja" ? "/ja" : "" -->
   </section>
   ```

3. **Create the two thin route wrappers.** English at `src/pages/my-page.astro`:

   ```astro
   ---
   import PageLayout from "../layouts/PageLayout.astro";
   import MyPage from "../components/pages/MyPage.astro";
   import { useTranslations } from "../i18n/index";

   const lang = Astro.currentLocale ?? "en";
   const t = useTranslations(lang);
   ---
   <PageLayout title={t.pages.myPage}>
       <MyPage lang={lang} />
   </PageLayout>
   ```

   Japanese at `src/pages/ja/my-page.astro` — identical except the import paths go up one more level (`../../`) and the fallback is `?? "ja"`.

4. **Add the nav link.** Edit the `navLinks` array in [Nav.astro](../src/components/layout/Nav.astro) (the mobile nav reuses it). Use the `base` prefix so it's locale-aware:

   ```ts
   { label: t.nav.myPage, href: `${base}/my-page` },
   ```

   (Add `myPage` to `t.nav.*` in the i18n files too.) To add a **footer** link instead, you edit data only — see [README → Navigation & footer links](../README.md#navigation--footer-links).

> [!Note]
> `<PageLayout>` already wraps the page in the site chrome and renders a `<Banner title={…}>`. Interactive widgets (React) are added as client islands — see [NewsletterFormCard.jsx](../src/components/ui/NewsletterFormCard.jsx) for an example of a React component embedded in an `.astro` page.

## Before you commit

- Run a production build — it type-checks the i18n keys and validates every collection entry against its schema, so a bad date or missing field fails here:

  ```sh
  npm run build
  npm run preview     # then check the page and /search
  ```
- Pushing to `master` **is the deploy** (GitHub Actions → GitHub Pages). PRs run the same build as a CI check. See [README → Deployment](../README.md#deployment).
